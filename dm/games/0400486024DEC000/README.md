# The Legend of Zelda: Ocarina of Time (`0400486024DEC000`)

A Switch 2 game: update v131072 over the base, surveyed from the user's `.nup` dump ([android/NUP.md](../../../android/NUP.md)), whose update package (`0400486024DEC800`, v131072) carries the whole game. SDK 22.2.8 built for the Switch 2, NVN2, NPLN 1.55.1. Nintendo EPD's engine (sead / agl / gsys, Phive, Havok, CRIWARE), modules `main` + `subsdk0` (NintendoSDK movie 22.2.8) + `sdk`. **In bring-up:** the profile holds the probe's measured identity and the phone split's measured shader tables ([shader_map.tsv](shader_map.tsv) with its facts and pairs); the memory map is the engine family's, not measured yet. Its closest relatives here are [Mario Kart World](../0400C3F00006E000/README.md) (the same engine with virtual address memory on, whose memory map this profile starts from) and [Donkey Kong Bananza](../040074A01BF12000/README.md) (the same engine, NVN2, Ampere shader code).

The probe report (2026-11-07, run on the phone with `scripts/nup_probe_termux.sh`): RomFS 186,583 files, 24.43 GB — `TerrainArc/*` scene terrain (Gerudo Fortress, Hyrule Field, Kakariko Village, Zora's Fountain, the Graveyard, Gerudo Valley, Desert Colossus, Haunted Wasteland, Zora's River, Death Mountain trail, ...), `Tex` 8.79 GB, `Model` 2.55 GB, `Sound/Resource/Stream` 1.73 GB, `Bake/Probe/Scene` 1.76 GB, `Event/Movie` 1.53 GB, `Phive/StaticCompoundBody`, `Foliage/Placement`, `Effect`. Code: `main` 60.3 MB text / 12.0 MB ro / 5.0 MB data, bss 1.3 MB; `sdk` 8.5 / 5.8 / 0.4; `subsdk0` 0.5 / 0.2 / 0.1. The `main` and `sdk` modules store their segments as ZBIC (Nintendo's zstd variant, system 22.0.0 on) — `dm/tools/nso.py` reads them through the `zbic` package.

The phone split (2026-11-07, the Prepare job's `dm/gfx/tools/shader_split.py` run — the same tool a Mac split runs): 42,321 shader variants — 22,356 pixel, 15,852 vertex, 4,101 compute, 9 mesh and 3 task (the family's second NVN2 mesh/task set, after Mario Kart World's 19 + 7); sources `/Effect/` 22,403, `/Shader/` 14,204 (`Model.Product.110.product.Nin_Ounce_NVN2.bfsha.zs` alone 12,897), `/Lib/` 5,569 (agl's built-ins), `/Layout2Shader/` 145, nothing under `/UI/`. Its four tables are committed here: [`shader_map.tsv`](shader_map.tsv) (the key the app's `splitMatchesProfile` compares byte for byte before translating), [`shader_facts.tsv`](shader_facts.tsv) (4,113 rows: the compute shaders' thread groups and shared memory, and the mesh programs' per-primitive codes with their pairs), [`shader_pairs.tsv`](shader_pairs.tsv) (26,894 vertex/pixel pairs within BNSH variations) and [`pso_pairs.tsv`](pso_pairs.tsv) (6,296 supplemental pairs). Every pair key is in the map.

## Open

- The first phone boot (2026-11-07) gets far: the engine-family memory map holds (heap 6.20 GB, alias fills as the family's), NVN2 comes up (window 2560x1440, 3 textures, pools placed by parts), audren renders on the CPU backend and the engine's threads run to about 1.3 s in. The boot's first stop was the `auddmg:u` connect ([the audio damage service `auddmg:u` at boot](../../../docs/reference/services.md#the-audio-damage-service-auddmgu-at-boot)), served since; the second (2026-11-07, main@c48e7e2) the proxy destructor's HIPC CloseSession right after the served connect (same section), served since too; the third (main@32047c9) sat at the same `sdk+0x2ace08` right after that close — the zeroed answers themselves — so the served session gave way to the audio take-overs (same section).
- The next phone boot (2026-11-07, main@7053d01) clears the audio stops and goes further: the shader library loads (42,228 shaders, 1,234.8 MB), the game renders and keeps booting to about 6.4 s in. The next stop is the NPLN setup ([eventfds served offline](../../../docs/reference/services.md#eventfds-served-offline)): a bare `nn::diag` abort at `sdk+0xb8fe8`, 0.3 s after the `_npln:` romfs mount, with the library's threads (`nn.npln.Worker`, `npln-grpc` executors, `Porter`, `LibcurlGc`) just up; the crash dump ran for seconds while the game's own threads kept presenting, then the process ended. main@ab104b3 reproduced it with no `[npln]` import-stub line at all — the game's modules import no `_ZN2nn4npln` symbol, so the import binding of the build between engaged nothing and the real cause stood open until the Mac/iOS tree's journal named it: gRPC's poll-engine wakeup eventfd, which the host's all-fail socket layer answered ENETDOWN. `hle_net.c` serves eventfds since (the Mac/iOS fix, with the `t_net_eventfd` test).
- `romfs_marker` names a file every EPD RomFS carries (`System/Resource/ResourceSizeTable.Product.rsizetable.zs`), but the exact name on this SDK is unconfirmed (the probe's listing holds the 20 largest top folders only); the Android flow does not read the key.
- `romfs_check`: no row yet. Donkey Kong Bananza checks line 4 of `System/RegionLangMask.txt` against main's build ID; whether this game's file carries the same line is unconfirmed.
- The display version is unknown (a `.nup` carries no control data): the build rows say `v131072` on both columns, as Pokémon Pokopia's do.
- The window size getters (`window_fn`) are the bring-up's to find; the render-condition and GPU-timestamp behaviour now follow the Mac/iOS profile's measured answers (`render_cond on`, `gpu_timestamps segment`).
- The three RomFS files their NUP carries damaged (12 KB of zeros at the head; the fairy fountain's `Tex/CmnTex_Map_Soil_FairyFountain_Floor_D_Nrm.bntx.zs` among them) have no `romfs_substitute` here yet: the key needs `hle_fs.c`'s `img_serve`, which this fork's NUP image layer does not carry (their `hle_fs.c` grew it on the NSP image). Without it the OptimizeChangeBanc thread re-asks the fairy fountain model about 22 times a second in Kokiri Forest (about 1.75 cores on their measurements), so the key is worth porting before long sessions.
- The split's task and mesh programs: the Mac/iOS split reads NVN2's BNSH program slots 7 and 8 and found 491 mesh + 17 task shaders against this tree's phone split (9 + 3), so models that draw through mesh shaders (their note names the door of Link's house) are expected missing until `shader_split.py`'s slot work is ported — its diff is some 720 lines, kept for its own round; the xlate cache keeps the existing 42,321 translations, so the re-split only translates the programs the map gains.

## Found on this game

- [The audio damage service `auddmg:u` at boot](../../../docs/reference/services.md#the-audio-damage-service-auddmgu-at-boot): the SDK 22 audio library opens it once the renderer runs and aborts on the refused connect; the served connect is then closed with an HIPC CloseSession the host refused, and the boot segfaulted in the SDK; both served since — and the boot still ended at `sdk+0x2ace08` just after the close, so the served session gave way to the take-overs of the SDK's own virtual-device functions in `hle_audio.c` (the Mac/iOS host's route, which never served the service): `GetDefaultVirtualOutputDevice` answers the host's output name, the `OpenOutputStream` pair opens AudioOuts of the host's, and the virtual input list comes back empty with null-safe state, purge and statistics for the two microphone streams the game asks after.
- [An asynchronous play report opens `prepo:u` at the first gameplay transition](../../../docs/reference/services.md#an-asynchronous-play-report-opens-prepou-at-the-first-gameplay-transition): `PlayReport::Send` opens its own session and the game aborted when it failed; the host now builds the completed `AsyncContext` in the caller's storage with the SDK's own constructor (a naked trampoline through x8), ported from the Mac/iOS fix.
- [Eventfds served offline](../../../docs/reference/services.md#eventfds-served-offline): the Switch 2 SDK 22 build's NPLN 1.55.1 aborted 0.3 s into its setup (`sdk+0xb8fe8`, no message, Result 0) on the phone boots of main@7053d01 and main@ab104b3 — gRPC's poll-engine wakeup eventfd, served by the host since (the Mac/iOS host's fix, which boots the same build to its title screen).
- [kid-with-sword-remake](https://github.com/cheemu21/kid-with-sword-remake), the Mac/iOS host of this same codebase, ran this exact build (`e0f3ccfaf50065ae…`) to the title, into the opening movie and to playable Kokiri Forest; this tree ported its audio virtual-device take-overs, the `prepo` `Send` completion, the profile keys above and its [`patches.py`](patches.py) — the movie player's NDVE cut (the enhanced player's Ampere tensor network cost 47.5 ms of GPU a movie frame there; the plain player shows the decoded picture as decoded, and spares the translator's unimplemented HMMA instructions) and the frame step (the game's own frame-rate controller at main+0x3b4f074 follows the host's vsync step, which the launcher's Frame rate setting drives). Their [game journal](https://github.com/cheemu21/kid-with-sword-remake/blob/main/dm/games/0400486024DEC000/README.md) is the map of what lies past the boot: the prewarmed NDVE pipelines, the render-condition scene, the mesh-shaded door, the bindless churn the later hosts fixed.
